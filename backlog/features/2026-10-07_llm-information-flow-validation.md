# Task: Validate Information-Flow Measures with LLM Agents

## Gating Note

This extension is subject to successful completion of the core CIP-0015 backlog through Gate 4.
It remains Proposed until the controlled campaign validates the environment, parsers, common decoder, estimators, and cost boundaries.
No model campaign should begin merely because this task exists.

## Description

Replace Bayesian or scripted policies with LLM-backed policies while preserving the controlled environment, neutral event contract, measurement points, and recording conditions.
Evaluate whether the core conclusions remain stable when decisions and messages are generated by language models.

## Motivation

The analytic environment provides internal validity but does not capture ambiguity, non-determinism, malformed outputs, or semantic variation from LLM agents.
An LLM validation layer tests whether the measurement protocol survives those practical conditions.

## Justification

LLM agents must not be introduced before the estimators are validated.
Otherwise estimator error and model behaviour become inseparable.
Keeping the same environment and structured measurement contract isolates the effect of replacing the policy while retaining comparability with the core experiment.

## Scope

The LLM receives the same observation information as the controlled policy.
It produces:

- a structured probability vector over the latent state
- a structured message from the declared alphabet or an explicitly decoded message
- a structured action from the declared action space
- optional natural-language reasoning that is not required by primary metrics

Every recording policy receives the same resulting neutral events.

## Execution Plan

1. Define one model-independent LLM policy interface.
2. Fix prompts, tools, model settings, temperature, retry rules, and malformed-output handling.
3. Ensure belief elicitation is identical across recording conditions.
4. Prevent recorder type or logging level from appearing in agent prompts.
5. Validate structured outputs on unscored pilot episodes.
6. Define treatment of abstentions, invalid probabilities, and missing actions.
7. Select models and campaign size from cost and variability pilots.
8. Reserve scored seeds and freeze prompts.
9. Run every scored execution through both implementations, holding the model outputs fixed across them.
10. Measure belief calibration, action accuracy, and information quantities.
11. Measure parser performance on structured and optional natural-language fields.
12. Compare information-retention conclusions with controlled policies.
13. Report model-call failures and discarded episodes.
14. Test sensitivity to at least one model or prompt variation if budget permits.
15. Decide whether evidence supports progression to Werewolf.

## Acceptance Criteria

- [ ] The same LLM outputs feed every recording condition.
- [ ] Recorder identity is absent from prompts and agent observations.
- [ ] Belief and action schemas are fixed before scored runs.
- [ ] Malformed-output handling is predeclared.
- [ ] Scored seeds and prompts are frozen.
- [ ] Belief entropy is reported with calibration.
- [ ] Validated core estimators are reused without post-result changes.
- [ ] Model failures and exclusions are fully accounted for.
- [ ] Information retention and model behaviour are reported separately.
- [ ] Differences from controlled-policy results are analysed.
- [ ] No Werewolf campaign is authorized without a Gate 5 review.

## Implementation Notes

Do not add a DOAgent-only explanation request.
Optional reasoning must be requested identically and offered to every recorder.
If natural-language messages require a semantic decoder, validate it separately and report its errors.

The primary comparison remains about retained representation.
Any behavioural difference between models is secondary.
